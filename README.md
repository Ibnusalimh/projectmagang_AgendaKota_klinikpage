# AgendaKota — Klinik Landing Page

A single-page React + TailwindCSS landing site for **AgendaKota for Klinik** — the clinic-focused product page of the AgendaKota platform. The page presents the value proposition, key benefits, testimonials, features, and a final call-to-action.

> Bootstrapped with [Create React App](https://github.com/facebook/create-react-app). The initial layout was scaffolded with [Builder.io](https://www.builder.io) (see the `// This code was generated by Builder.io.` header in `src/App.jsx`).

## Overview

This repo is one of three sibling landing-page apps from the AgendaKota internship project:

| Repo                                             | Purpose                                   |
| ------------------------------------------------ | ----------------------------------------- |
| `projectmagang_AgendaKota_klinikpage` (this)     | "Untuk Klinik" landing page               |
| `projectmagang_AgendaKota_fiturpage`             | "Fitur" landing page                      |
| `projectmagang_AgendaKota_harga`                 | "Biaya" (pricing) landing page            |

It is a **read-only marketing page**: no auth, no API. Content is hard-coded in the React components, with images sourced from the Builder.io CDN.

The page renders five vertically stacked sections via `src/components/MainContent.jsx`:

```
<MainContent>
  <Header />            // logo + nav + Log In / Sign Up CTAs
  <BenefitSection />    // 4 benefit cards
  <TestimonialSection />
  <FeatureSection />
  <CallToAction />
</MainContent>
```

## Features

- **Static, fast-loading marketing page** — no client-side data fetching, ideal for CDN hosting.
- **Tailwind-first styling** — utility classes throughout, configured in `tailwind.config.js`.
- **Modular component design** — every visual block (`Header`, `BenefitCard`, `FeatureCard`, `PricingCard`, `FAQItem`, `CTASection`, …) is a small reusable component under `src/components/`.
- **Responsive layout** — uses Tailwind's `md:` breakpoint utilities (`md:grid-cols-2`, `md:px-5`, etc.).
- **Sections**:
  - **Header** with logo, primary nav (Tentang Agendakota, Fitur, Untuk Klinik, Biaya, Hubungi Kami), and Log In / Sign Up buttons.
  - **Benefit** — 4 cards: *Reservation Management*, *Marketing Analytics*, *AI Marketing Generator*, *Marketing Tools*.
  - **Testimonial** — customer quotes.
  - **Feature** — feature cards with icons.
  - **Call To Action** — bottom-of-page conversion section.
- **Reusable primitives** — `Button`, `Logo`, `NavItem`, `ProfileIcon`, `SectionHeader` are shared across sections.

## Getting Started

### Prerequisites

- Node.js 18+ and npm

### Install & run

```bash
git clone https://github.com/zXmill/projectmagang_AgendaKota_klinikpage.git
cd projectmagang_AgendaKota_klinikpage
npm install
npm start                # http://localhost:3000
```

### Build for production

```bash
npm run build            # outputs to ./build
```

Deploy `build/` to any static host (Netlify, Vercel, GitHub Pages, S3 + CloudFront, …).

## Code Review Notes

Quick observations from reading the code — none are blockers, just things worth tightening up:

1. **`package.json` name mismatch** — the package name is `"fiturpageak"` even though this repo is the **klinik** page. Rename to `klinikpageak` (or similar) for clarity.
2. **Self-referential dep** — `"fiturpageak": "file:"` is a leftover from local linking and can be removed.
3. **`ReactDOM.render` (legacy API)** — `src/index.jsx` still uses the React 17 entry point. With React 18 you should switch to `createRoot` to opt into concurrent features:
   ```js
   import { createRoot } from 'react-dom/client';
   createRoot(document.getElementById('root')).render(<React.StrictMode><App /></React.StrictMode>);
   ```
4. **Hard-coded copy & images** — section content (benefit titles, testimonial text, feature descriptions) and image URLs live directly in components. Extract to a `src/data/` JSON/JS module so editors can update copy without touching components, or wire it into the Strapi CMS used by the parent `projectmagang` repo.
5. **Builder.io CDN dependency** — `BenefitSection`, `FeatureCard`, etc. reference `https://cdn.builder.io/...`. If the Builder workspace ever changes API keys or removes the assets, the page silently breaks. Mirror critical images into `src/assets/` and import them locally.
6. **Anchor links go nowhere** — every `NavItem` `href` is `#`. Replace with real routes or smooth-scroll anchors (`#benefit`, `#features`, etc.).
7. **`Navigation.jsx` is dead code** — `Header.jsx` builds its own inline nav and never imports `Navigation`. Either delete `Navigation.jsx` or refactor `Header` to use it.
8. **Tailwind config is empty** — `tailwind.config.js` has no `theme.extend`. Adding the brand color palette and font family centrally would let components stop repeating raw `text-slate-600`, etc.
9. **No accessibility metadata** — `Header.jsx`'s nav uses `<ul>`/`<li>` but is missing `aria-label`. Buttons have only visible text (`Log In`, `Sign Up`) — fine, but add `aria-current` / focus styles to nav items.
10. **No tests** — `@testing-library/*` is installed but `src/` ships no test files. Even a smoke test that `App` renders the five top-level sections would be a useful regression check.
